# 展品点交与交接链追踪（展馆 × 运输）

纯 Node.js 内置模块实现，无第三方依赖。模拟展馆端与运输端各自开具装箱 / 转运 / 开箱交接单，统一采集、去重、按发生时间重放校验，并支持物件级交接链查询与箱换编号回溯。

## 运行

```bash
node server.js          # 默认 3000 端口
PORT=3100 node server.js # 读取 PORT，绑定 127.0.0.1
```

打开 http://127.0.0.1:3000 ，页面上可依次操作：

- **采集两边交接单**：拉取展馆 / 运输两侧 outbox，重复交单按单号去重（样例中 PK-001 同侧重投、TR-002 两侧各留一份底单）；
- **补交早到记录**：补录 TR-001（发生时间早于到馆签收），交接链断点随之修复；
- **打开物件交接链**：任选物件查看完整经手时间线（含换编号、部分转交、补录标记）；
- **箱位置报告**：输入任意历史箱号（如 BOX-100 或换号后的 BOX-200）都能回到原箱并看到完整交接链。

业务结果区带 `data-evidence-result` 属性，方便核对操作前后内容。

## 测试

```bash
node --test
```

覆盖：正常流程（采集去重、全量重放、换编号回溯、部分转交、补交早到记录）与异常流程（重复交单、未知物件、结构非法、转运不在箱中的物件、开箱未知箱、重复开箱、重复补交、交接链断点）。

## 设计要点

- **采集与校验分离**：采集只做结构校验与按 `slipId` 幂等去重；状态由全部已收单据按 `(发生时间, 受理序号)` 重放折叠得出，绝不只取最后一条。
- **补交早到记录**：晚到的单据按发生时间插回正确位置并打 `late` 标记，状态随之重算（补上前断点报警，补上后校验通过）。
- **箱换编号**：`renumberTo` 建立「新编号 → 原箱」别名，任意历史编号的位置报告都解析到同一规范箱，标签链与事件链完整保留。
- **物件级追踪 + 箱标签关联**：整箱转运按箱走（成本低），部分转交按物件在箱间移动（谁在哪只箱里始终精确）；只转交部分展品时源箱持有方不变、目标箱归接收方。
- **校验问题**：持有方与票面交方不一致（断点）、物件不在箱中、未知箱、重复开箱、重复装箱等都以结构化问题列出，不静默吞掉。

## 目录

```
server.js          HTTP 服务（node:http，读 PORT，绑 127.0.0.1）
src/ledger.js      台账核心：采集、去重、重放、校验、交接链/位置报告
src/seed.js        本地样例数据（两侧 outbox + 一条迟到的早到记录）
public/index.html  操作页面（结果区带 data-evidence-result）
test/              node --test 用例（领域逻辑 + HTTP 冒烟）
```
